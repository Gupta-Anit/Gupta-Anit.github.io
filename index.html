Semantic layer for agents

Governed metric and dimension definitions that analytics agents query instead of raw tables, so "active subscriber" or "attributed sign-up" means the same thing to an agent as it does to finance.

Context layer

The business context agents need beyond metric definitions: what each table and column means, who owns it, how fresh it is, and the caveats an experienced analyst would know. Agents pull this in before they write a query.

Open Knowledge Format (Google OKF)

Data knowledge written as linked Markdown files with YAML frontmatter, following Google Cloud's open spec, so the same context can be versioned in Git and served to agents through a knowledge catalog instead of living in scattered wikis and code comments.

Guardrails and evals

Checks that stop agents from inventing numbers, plus evaluation sets that test answers against known results before a change ships.

Data Engineering Agents (Google ADK)

A proof-of-concept framework of cooperating agents, built on Google's Agent Development Kit and A2A, that help build pipelines and run data quality checks, with cost controls for agents that query large BigQuery tables.

Skill files

Packaged, reusable instructions that give agents team-specific know-how, such as table context, SQL conventions and runbooks, so they follow how the team actually works.

LangGraph and LangChain

Multi-step agent workflows with explicit state, tool calls and retrieval over warehouse metadata.

LLM content-trait pipeline

stage 04featured project

streamscope: exactly-once streaming on a lakehouse

Kafka (KRaft)Flink SQL 1.18Iceberg 1.5TrinoMinIODocker Compose
View on GitHub ↗

Ingests live Wikipedia edit events, filters bot edits, computes per-wiki one-minute tumbling windows on event time with a 30-second watermark, and commits the results to Iceberg for SQL and time-travel queries in Trino. The whole stack starts with one docker compose up.

How exactly-once holds
  • Kafka offsets live in Flink checkpoint state, so a restart rewinds to the last checkpoint.
  • Flink snapshots state and offsets to object storage every 30 seconds.
  • Iceberg commits a snapshot only when a checkpoint completes, so writes from a failed task are discarded.
